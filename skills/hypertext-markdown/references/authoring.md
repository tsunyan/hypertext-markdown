# hypertext-markdown の書式

標準の Markdown（GFM）に足した書式だけをまとめる。見出し・リスト・表・コードブロック・リンク・強調・取り消し線・タスクリスト・脚注（`[^1]`）・注記（`> [!NOTE]` など）・Mermaid（`` ```mermaid ``）は、GitHub と同じ書き方でそのまま使える。

## 文書の構造

見出しが、目次・章番号・スライドの区切りになる。構造を先に決めてから書く。

- `#`（H1）は文書名の代わりにだけ使う。フロントマターに `title` があれば書かない
- `##`（H2）が章、`###`（H3）が節。目次に出るのはこの 2 段
- スライドは表紙 + H2 ごとに 1 枚（`slide_level: 3` なら H3 ごと）。1 つの章や節が長すぎると、文字を縮めたうえで自動で次のスライドに送られる。スライドで見せる文書は、節を短く保つ
- 見出しの末尾に `{-}` を付けると章番号を振らない（`## 改版履歴 {-}`）。`{#ID}` を付けると `[](#ID)` で参照できる

## フロントマター

本文の先頭に `---` で囲んで書く。どれも省略できる。

| キー | 内容 |
|---|---|
| `title` | 文書名。無ければ先頭の `# 見出し` を使う |
| `subtitle` | 副題 |
| `docid` / `version` | 文書番号・版 |
| `date` / `updated` | 作成日・更新日（`2026-11-10`） |
| `author` / `reviewer` / `approver` | 作成・レビュー・承認 |
| `status` | `draft` / `review` / `approved` / `final` / `obsolete`。表紙に印が付く |
| `classification` | 機密区分（`社外秘` など）。表紙と印刷時のヘッダーに出る |
| `numbering` | `true` で H2・H3 に章番号を振る |
| `slide_level` | `3` で H3 でもスライドを分ける（既定は `2`） |
| `h2_pagebreak` | `true` で印刷時に H2 の前で改ページ |
| `filename` | 画面で保存するときのファイル名（拡張子なし） |
| `palette` | 強調の色の組。`indigo`（標準）・`blue`・`teal`・`green`・`wine`・`orange`・`purple`・`gray` |
| `accent` | 強調の色を直接指定。`"#0f6e6e"`、またはダーク用も `"#0f6e6e / #6fcfc9"`。`palette` より優先 |
| `font` | 本文の書体。`gothic`（標準）・`ud`・`meiryo`・`yugothic`・`noto`・`system`・`mincho`、または書体名の並び |
| `mono` | コードの書体。書体名の並び（`"Cascadia Code", Consolas`） |
| `logo` | 表紙とスライドに出すロゴ。URL・`data:` URL・参照形式の名前（`logo: logo` と書き、末尾に `[logo]: data:…`） |

表に無いキー（`customer: 〇〇株式会社` など）も、表紙の欄にそのまま並ぶ。

## 囲み（:::）

`:::名前` で始めて `:::` で閉じる。中身は普通の Markdown。

```markdown
:::名前 タイトルなど {#ID .クラス}
（中身）
:::
```

- 名前の後ろの文字は、部品に応じてタイトル・見出し・表題・出典になる
- `{#ID .クラス}` は省略できる。ID は `[](#ID)` で参照できる（`figure`・`table` は番号に置き換わる）
- 入れ子にするときは外側を `::::` と長くする
- Zenn と同じ `:::message`・`:::message alert`・`:::details タイトル` も使える
- 一覧に無い名前は `c-名前` クラスの `div` になる（CSS はテンプレート先頭の `<style>` に書く）

### 流れ

`:::steps` 手順。番号付きリストで、先頭の太字が手順名、次の行（字下げ）が説明。

```markdown
:::steps
1. **サービスを停止する**
   `systemctl stop app` を実行する
2. **パッチを適用する**
:::
```

`:::flow` 工程の流れ（矢印でつないで横に並ぶ）。リストで、先頭の太字が工程名。

```markdown
:::flow
- **設計**
  方式と機能を決める
- **実装**
- **試験**
:::
```

`:::timeline タイトル` 時系列。リストで、先頭の太字（または「：」の前）が日時。

```markdown
:::timeline 障害の経緯
- **11/10 09:00** 監視で遅延を検知
- **09:40** 設定を変更して復旧
:::
```

### 並べる・比べる

`:::cards` カード。リスト（先頭の太字が見出し）か、`####` 見出しごと（中に表やコードも書ける）。

```markdown
:::cards
- **可用性** 年間の停止時間を 4 時間以内にする
- **性能** 応答を 2 秒以内にする
:::
```

`:::columns 比` 段組み。`---` か見出しで区切る。`:::columns 1:2` で幅の比。

```markdown
:::columns 1:1
**現行の課題**

- 手作業が多い

---

**移行後の姿**

- 定型作業を自動化
:::
```

`:::compare` 案の比較。`####` 見出しごとに 1 案。推奨の案の見出しに `{.best}`。

```markdown
:::compare
#### 案A オンプレミス継続
- 初期費用：小

#### 案B クラウド移行 {.best}
- 初期費用：中
:::
```

`:::pros-cons` メリット・デメリット。`---` の前がメリット、後ろがデメリット（見出しを書けばその名前になる）。

```markdown
:::pros-cons
- 保守が不要になる

---

- 通信費が増える
:::
```

`:::tabs` タブ。`####` 見出しごとに 1 タブ（見出しがタブ名）。印刷では全部並ぶ。

````markdown
:::tabs
#### Windows
```powershell
Get-Service app
```

#### Linux
```bash
systemctl status app
```
:::
````

### 強調

`:::summary` 要旨（冒頭に置く）。名前の後ろに書くと見出しを変えられる。`:::lead` スライドで大きく見せる一文。

```markdown
:::summary
2027 年 3 月の保守切れに備え、2026 年度中にクラウドへ移行する。
:::

:::lead
移行の目的は、運用の手間を半分にすることです。
:::
```

`:::metrics` 数値の強調。リストで、先頭の太字が数値。`:::progress タイトル` 進捗バー。リストで、末尾が割合。

```markdown
:::metrics
- **99.95%** 月間の可用性
- **1.2 秒** 平均の応答時間
:::

:::progress 移行作業の進捗
- 設計 100%
- データ移行 35%
:::
```

### 補足

`:::note` `:::tip` `:::important` `:::warning` `:::caution` 注記。名前の後ろがタイトル。`> [!NOTE]` と同じ見た目で、タイトルを付けられる。

`:::details 見出し` 折りたたみ（印刷では開く）。

```markdown
:::warning 作業の前に確かめること
- 直前のバックアップが取れていること
:::

:::details 実行ログの全文
（長いログ）
:::
```

`:::qa` 想定問答。`####` 見出しが質問、その下が回答。

```markdown
:::qa
#### 停止時間はどのくらいですか？
約 30 分です。
:::
```

`:::quote 出典` 出典付きの引用。

```markdown
:::quote 〇〇省「△△ガイドライン」2026 年版 第 3 章
復旧の手順を定め、定期的に訓練すること。
:::
```

### 構成

`:::figure {#ID} 表題` と `:::table {#ID} 表題` 図表番号付きの図・表。表題は図では下、表では上に付く。本文の `[](#ID)` が「図 1」「表 1」に置き換わる。

```markdown
:::table {#tbl-env} 環境ごとの台数
| 環境 | Web | DB |
|---|---:|---:|
| 本番 | 2 | 2 |
:::

台数は [](#tbl-env) のとおり。
```

`:::spec タイトル` 項目と値の一覧。リストで「**項目**：値」。

```markdown
:::spec サーバーの構成
- **OS**：RHEL 9.4
- **CPU / メモリ**：4 vCPU / 16 GB
:::
```

`:::tree` ツリー。入れ子のリストを線でつなぐ。

```markdown
:::tree
- `app/`
  - `config/`
    - `app.yml`
  - `README.md`
:::
```

### 出し分け

`:::doc-only` は読み物だけ、`:::slide-only` はスライドだけに出す。スライドには要点、読み物には詳しい説明を載せるときに使う。

```markdown
:::doc-only
詳しい経緯と根拠（読み物だけに出る）。
:::

:::slide-only
- 要点 1
- 要点 2
:::
```

### グラフ

`:::chart 種類 表題 unit=単位 min= max=` の中に Markdown の表か `` ```csv `` を書く。1 列目が項目、2 列目以降が系列（8 系列まで）。

| 種類 | 見せ方 |
|---|---|
| `bar`（省略時） | 縦棒。項目ごとの大きさを比べる |
| `barh` | 横棒。項目名が長い、項目が多い |
| `stacked` | 積み上げ縦棒。合計と内訳 |
| `line` | 折れ線。時間による変化 |
| `area` | 面。変化と量 |
| `share`（`pie` も可） | 構成比の帯。全体に占める割合（6 項目程度まで） |

```markdown
:::chart line 画面の平均応答時間 unit=秒
| 月 | 本番 | 検証 |
|---|---:|---:|
| 4月 | 1.4 | 2.3 |
| 5月 | 1.2 | 2.0 |
:::
```

`unit=` を省くと、数値の後ろにそろって付いている単位（`%` など）を使う。`min=0 max=100` で軸の範囲を決める。

### 用語集

`:::glossary` に「**用語**：意味」のリストを書くと、本文中のその用語に意味が添えられる（H2 の章ごとに最初の 1 回）。用語集に載せない略語は、どこかの行に `*[略語]: 意味` と書く（この行は表示されない）。

```markdown
:::glossary
- **SLA**：サービス品質の合意
- **RTO**：目標復旧時間
:::

*[RPO]: 目標復旧時点
```

### 改版履歴

`:::history` と `:::` の 2 行だけを書くと、ファイルに記録された確定版の一覧が表になる。版の確定は人が画面で行う（<kbd>V</kbd>）ので、版のデータは書かない。版が無いうちは「確定した版はまだありません」と出る。

```markdown
## 改版履歴 {-}

:::history
:::
```

### 見本

`:::example` 中身を描いたものと元の Markdown を、「表示」と「書き方」のタブで並べる。書式の説明書を作るとき以外は使わない。

## 文中の記法

| 書き方 | 表示 |
|---|---|
| `:ok[完了]` `:warn[保留]` `:ng[未対応]` `:info[確認中]` `:tag[任意]` | 状態のラベル。表の中でも使える |
| `:menu[設定 > ネットワーク > プロキシ]` | 画面の操作経路 |
| `==語==` | 蛍光ペン |
| `<kbd>Ctrl</kbd>+<kbd>C</kbd>` | キー |
| `[](#ID)` | 章番号・図表番号への参照（文字は自動で入る） |
| `**「強調」**` | 日本語の記号の直後で閉じる強調も効く |

## コード・表

- コードブロックの言語名の後ろに `:ファイル名` か `title="ファイル名"` を書くと、ファイル名が付く（`` ```bash:deploy.sh ``）
- 色分けする言語: `c` `cpp` `cs` `java` `js` `ts` `py` `bash` `bat` `powershell` `sql` `html` `xml` `css` `md` `json` `yaml` `toml` `ini`（別名も可）。それ以外の言語は色分けせずに表示する
- `` ```csv `` / `` ```tsv `` は表になる。1 行目が見出し。`noheader` で 1 行目も中身に、`title="…"` で表題、`code` を付けるとソースのまま表示
- `` ```diff ``（`patch`）は GitHub の差分画面のように表示する。`` ```diff split `` で最初から左右表示、`` ```diff lang=python `` で中のコードの言語を指定（省くとファイル名の拡張子から決める）

## 画像

- 画像だけの段落は中央に置かれ、代替テキストが表題になる。番号を付けるときは `:::figure` で囲む
- 1 つのファイルで配るので、画像は `data:` URL で埋め込む。本文には `![構成図][arch]` と名前だけを書き、`[arch]: data:image/png;base64,…` を末尾に置く（参照形式）
  - `scripts/build.mjs` を使うなら、手元のファイルを `![構成図](./arch.png)` と書くだけでよい（自動でこの形にする）
- テーマに合わせて出し分けるときは、URL の末尾に `#gh-light-mode-only` と `#gh-dark-mode-only` を付けた 2 枚を並べる
- SVG は本文に `<svg>` を直接書くと、`var(--accent)` などの色の変数と `currentColor` が効き、テーマに追従する。途中に空行を入れない
- 画像は縮小してから入れる（base64 は元の約 1.33 倍になり、保存した HTML には 2 か所に入る）

## スライドと印刷の制御

| 書き方 | 効果 |
|---|---|
| `<!-- slide -->`（1 行で） | ここでスライドを区切る。読み物では見えない |
| `<!-- pagebreak -->`（1 行で） | 印刷で改ページし、スライドも区切る |
| `slide_level: 3` | H3 ごとにスライドを分ける |
| `h2_pagebreak: true` | 印刷で H2 の前に改ページ |

## HTML を直接書く

- 文の中のタグ（`<kbd>` `<mark>` `<sub>` `<sup>` `<br>` など）は表示用の許可リストにあるものだけ残る
- 行の先頭をブロックのタグ（`<div>` `<details>` `<table>` `<figure>` など）で始めると、次の空行までが HTML になり、その中の Markdown は解釈されない。中で Markdown を使うときは、タグの行との間に空行を入れる
- `script`・`style`・`iframe`・フォーム、`onerror` などのイベント属性、`data-*`、危険な URL は取り除かれる
- `style` 属性は余白・枠・色・配置などの表示用 CSS だけ使える。`url()`・`position`・`z-index` などは取り除かれる
- `ui-` で始まる ID と重複する ID は使えない。SVG は表示用のタグと内部参照だけ使える
- `class` は `c-` で始まる自作用の名前だけ使える。画面の部品と同じクラスは取り除かれる
- 本文に `</script>` と書くと Markdown のブロックが終わってしまう。`scripts/build.mjs` は自動で `<\/script>` に書き換える。HTML を手で編集するときは自分で書き換える

## 雛形

調査報告:

```markdown
---
title: 〇〇の調査報告
author:
date: 2026-11-10
status: draft
---

:::summary
（結論を 2〜3 行で）
:::

## 背景と目的
## 調査方法
## 結果
## 考察と推奨事項
## 参考資料
```

設計書:

```markdown
---
title: 〇〇システム 基本設計書
docid:
version: 0.1
date: 2026-11-10
author:
status: draft
classification: 社外秘
numbering: true
h2_pagebreak: true
---

## 改版履歴 {-}

:::history
:::

## はじめに
### 目的
### 対象範囲
### 用語

:::glossary
- **用語**：意味
:::

## システム概要
## 方式設計
## 機能設計
## 非機能設計
## 運用設計
```

障害報告:

```markdown
---
title: 〇〇システム 障害報告
date: 2026-11-10
status: review
classification: 社外秘
numbering: true
---

## 概要

:::spec
- **発生日時**：
- **影響範囲**：
- **状態**：:ok[復旧済み]
:::

## 経緯

:::timeline
- **09:00** 
:::

## 原因
## 対策
## 再発防止策
```
