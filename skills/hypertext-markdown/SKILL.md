# hypertext-markdown で文書を作る

Markdown を書き、`scripts/build.mjs` で空のテンプレートに流し込んで、1 つの HTML ファイルにする。できた HTML はブラウザで開くだけで読め、外部のサーバーは要らない。

## ファイル

- `references/authoring.md`: 標準の Markdown にない書式と雛形。文書の構造・フロントマターを確認し、部品や雛形は使う節だけ読む
- `scripts/build.mjs`: `.md` を HTML にする（Node.js 18 以上、依存なし）。通常はソースを読まず、以下のコマンドを実行する
- `assets/template.html`: スクリプトが読む空のテンプレート。通常の文書作成・修正では、AI は内容を読まず、直接編集もしない

このファイルのあるフォルダを、以下では `<skill>` と書く。

## コンテキストに入れるもの

通常は、この手順・必要な書式の説明・執筆する Markdown だけを読む。テンプレート、利用ガイドや見本の HTML、生成した HTML のソース全文はツールの出力に載せない。HTML の読み書きと画像の埋め込みは `build.mjs` に任せる。ブラウザでの確認は、表示とエラーを対象にする。

テンプレートの実装変更や不具合調査を頼まれた場合だけ、関連する CSS・JavaScript などを必要な範囲で読む。

## 新しく作る

1. **構成を決める。** 読み手と用途（読み物か、スライドで見せるか、印刷するか）を確かめ、H2 の章立てを決める。種類が合えば `authoring.md` の雛形から始める
2. **Markdown を書く。** 見出し・表・リストなど普通の書式を基本にし、普通の書式では伝わりにくいところだけ部品を使う（手順は `:::steps`、案の比較は `:::compare`、数値の推移は `:::chart` など）。画像は手元のファイルを `![説明](./fig.png)` と書けばよい
3. **HTML にする。**

   ```bash
   node <skill>/scripts/build.mjs report.md
   ```

   `report.html` ができる。出力先は `-o 出力.html` で変えられる。画像が見つからないときはエラーで止まるので、パスを直して実行し直す
4. **確かめる。** ブラウザを操作できるなら HTML を開き、エラーが出ないこと、部品が意図どおりに描かれることを見る。スライドで使う文書なら <kbd>S</kbd> で各スライドを見る（収まらない分は自動で縮小・分割される）
5. **渡す。** HTML のパスと、主な操作を伝える: <kbd>S</kbd> スライド、<kbd>E</kbd> 編集、<kbd>Ctrl</kbd>+<kbd>P</kbd> 印刷・PDF、<kbd>V</kbd> 版の管理、<kbd>?</kbd> ショートカットの一覧

## ロゴと favicon を指定する

画像の内容や HTML を読み込まず、ファイルのパスを渡す。

```bash
node <skill>/scripts/build.mjs report.md --logo ./logo.svg --logo-dark ./logo-dark.svg --favicon ./favicon.png --favicon ./favicon.svg
```

- パスはコマンドを実行するフォルダ基準。絶対パスも使える。画像は HTML に埋め込まれ、配布時に別添は不要
- `--logo` だけなら明暗共通。`--logo-dark` を添えるとダーク用を分けられる。ダーク用だけの変更も可能
- `--favicon` は SVG・PNG・ICO に対応し、複数回指定できる。指定した一式で既存の favicon を置き換える
- 省略した設定はテンプレートから引き継ぐ。ただし `--logo` だけを指定した場合、既存のダーク用ロゴは外す
- ロゴはテンプレートの既定値を変える。Markdown のフロントマターに `logo` があれば、そちらが優先する
- `--template` と併用でき、既存文書の修正にも同じオプションを使える

## 既存の HTML を直す

hypertext-markdown の HTML は、ファイルの中の Markdown が正本。描画された本文を直接直しても、次に開いたときに Markdown から描き直されて消える。

HTML を開いてソースを読む前に、次のコマンドで Markdown をファイルに取り出す。AI が読んで直すのは取り出した `.md` だけとする。画像の `data:` URL が含まれる場合は、その長い定義を出力せず、本文の必要な範囲を読む。定義自体はファイルに残す。

```bash
node <skill>/scripts/build.mjs --extract report.html -o report.md
（report.md を直す）
node <skill>/scripts/build.mjs report.md --template report.html --keep-versions -o report.html
```

- `--template report.html` で、その文書のテンプレート（ロゴや色の設定）をそのまま使う
- `--keep-versions` で、利用者が確定した版を残す。付けないと版が消えるので、既存の文書では必ず付ける
- 版の確定は利用者が画面で行う。版のデータを自分で作ったり書き換えたりしない

## 気を付けること

- `:::history` は、版が確定されるまで「確定した版はまだありません」と表示される。設計書のように改版履歴が要る文書にだけ入れる
- Mermaid の図は、開いたときに CDN から描画ライブラリを読む。オフラインで読まれる文書では、図を SVG（本文に `<svg>` を直接書く）か画像にする
- 本文の HTML は表示用の許可リストで無害化される。`script`・`style`・`iframe`・フォーム、イベント属性、危険な URL などは使えない。文書ごとの見た目は、安全な `style` 属性か、指定されたテンプレート側の CSS で整える
- 自社のロゴや色を既定にしたテンプレートや、指定されたデザインの見本を使うときは、HTML の中身を読まずにパスを `--template` に渡す。新規作成では `--keep-versions` を付けず、見本の確定版を引き継がない。文書ごとの色やロゴは、フロントマターの `palette`・`accent`・`logo` で変える
