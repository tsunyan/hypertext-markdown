# hypertext-markdown で文書を作る

Markdown を書き、`scripts/build.mjs` で空のテンプレートに流し込んで、1 つの HTML ファイルにする。できた HTML はブラウザで開くだけで読め、外部のサーバーは要らない。

## ファイル

- `references/authoring.md`: 標準の Markdown にない書式（フロントマター、`:::` の部品、文中の記法、雛形）。書き始める前に読む
- `scripts/build.mjs`: `.md` を HTML にする（Node.js 18 以上、依存なし）
- `assets/template.html`: 空のテンプレート。直接編集しない

このファイルのあるフォルダを、以下では `<skill>` と書く。

## 新しく作る

1. **構成を決める。** 読み手と用途（読み物か、スライドで見せるか、印刷するか）を確かめ、H2 の章立てを決める。種類が合えば `authoring.md` の雛形から始める
2. **Markdown を書く。** 見出し・表・リストなど普通の書式を基本にし、普通の書式では伝わりにくいところだけ部品を使う（手順は `:::steps`、案の比較は `:::compare`、数値の推移は `:::chart` など）。画像は手元のファイルを `![説明](./fig.png)` と書けばよい
3. **HTML にする。**

   ```bash
   node <skill>/scripts/build.mjs report.md
   ```

   `report.html` ができる。出力先は `-o 出力.html` で変えられる。画像が見つからないときはエラーで止まるので、パスを直して実行し直す
4. **確かめる。** ブラウザを操作できるなら HTML を開き、エラーが出ないこと、部品が意図どおりに描かれることを見る。スライドで使う文書なら <kbd>S</kbd> で各スライドを見る（収まらない分は自動で縮小・分割される）
5. **渡す。** HTML のパスと、主な操作を伝える: <kbd>S</kbd> スライド、<kbd>E</kbd> 編集、<kbd>Ctrl</kbd>+<kbd>P</kbd> 印刷・PDF、<kbd>V</kbd> 版の管理、<kbd>?</kbd> ショートカットの一覧

## 既存の HTML を直す

hypertext-markdown の HTML は、ファイルの中の Markdown が正本。描画された本文を直接直しても、次に開いたときに Markdown から描き直されて消える。

```bash
node <skill>/scripts/build.mjs --extract report.html -o report.md
（report.md を直す）
node <skill>/scripts/build.mjs report.md --template report.html --keep-versions -o report.html
```

- `--template report.html` で、その文書のテンプレート（ロゴや色の設定）をそのまま使う
- `--keep-versions` で、利用者が確定した版を残す。付けないと版が消えるので、既存の文書では必ず付ける
- 版の確定は利用者が画面で行う。版のデータを自分で作ったり書き換えたりしない

## 気を付けること

- `:::history` は、版が確定されるまで「確定した版はまだありません」と表示される。設計書のように改版履歴が要る文書にだけ入れる
- Mermaid の図は、開いたときに CDN から描画ライブラリを読む。オフラインで読まれる文書では、図を SVG（本文に `<svg>` を直接書く）か画像にする
- 本文に書いた HTML は無害化されない。script 要素は動かないが、`onerror` などのイベント属性は開いた人のブラウザで動く。外から受け取った文章を貼るときは、そうした属性が無いかを確かめる
- 自社のロゴや色を既定にしたテンプレートを使うときは `--template` で指定する。文書ごとの色やロゴは、フロントマターの `palette`・`accent`・`logo` で変える
